# State-transfer experiment proposal

Status: non-normative RFC for independent review. Tracks [issue #42](https://github.com/Moissanite-Labs/abios/issues/42).

The proposed first experiment asks whether a compatible model can receive
reasoning state with better task quality per unit cost than ordinary context
reuse or a text handoff. It requires one pinned open model and an external
runner. ABIOS describes the exchange; the runner imports state; Synbios records
artifact revisions, evidence and review. This proposal adds no runtime, wire
commands, mandatory gates or permission to load model state.

## Boundaries

| Mechanism | First experiment |
| --- | --- |
| Full context and identical-prefix/KV reuse | Baselines, with cold and warm conditions separated |
| Text or structured-summary handoff | Baseline using the same task information and tools |
| Learned latent/reasoning-state handoff | Candidate, only with a pinned compatible runner |
| Generated LoRA or adapters | Deferred offline study |
| Persistent weight editing | Deferred, with its own regression and restore plan |

The ABIOS/3 proposal in [#38](https://github.com/Moissanite-Labs/abios/pull/38)
excludes a latent channel under S-14. This experiment needs a separately
versioned companion contract. It must preserve the command stream's lossless
reconstruction requirements. Tensor bytes remain outside that stream.
Ordinary prefix reuse is not evidence of latent reasoning, and fewer output
tokens do not by themselves establish lower total compute or better reasoning.

## Proposed manifest

Use a separately stored JSON manifest with a representation kind and explicit
contract version. Record these groups before any import:

| Group | Required information |
| --- | --- |
| Identity | Representation kind/version; SHA-256 and byte length of every object; storage reference and retention scope |
| Producer and consumer | Exact model/checkpoint and adapter revisions; serving implementation revision; tokenizer revision where relevant |
| Cache binding | Exact prefix/context digest; position and mask state; layer/attention layout, shape, dtype and serialization format |
| Scope | Task identifier, permitted use, provenance, resource limits, expiry and authenticated authorization reference |
| Compatibility | Supported import/export interfaces, exact compatibility checks, explicit unsupported result and recovery behavior |
| Evidence | Immutable manifest revision/digest, task-set revision, run records, evaluation artifact references and reviewer decision |

Matching dimensions alone is insufficient. The runner must validate object
hashes, revisions, context bindings, authorization and resource limits before
deserialization/import. It must use a safe, declared serialization format and
must not execute code supplied by a state artifact. A hash establishes byte
identity, not fidelity, compatibility or permission.

For the pilot, serialize the manifest once as UTF-8 JSON and hash those exact
stored bytes; do not regenerate it from a database projection for verification.
Any change creates a new immutable manifest revision. A later interoperable
contract must define canonical serialization explicitly. The manifest digest
belongs in the external artifact record, avoiding a self-referential hash.

Keep access to raw state and caches within the access and retention rules for
their source context. A text fallback must be a separate declared condition;
it cannot be described as lossless recovery of arbitrary latent state. Never
silently substitute another model, adapter, cache or fallback.

## Synbios recording contract

Start with an existing `document` artifact referencing the immutable manifest.
Bind its revision and digest to the exact stored manifest bytes. Attach each
evaluation as evidence for that artifact revision. The runner verifies tensor
bytes against the manifest; Synbios records the binding and does not fetch or
attest tensors. Follow its existing authenticated commands and independent
review lifecycle; introduce no parallel authority system.

A changed model, adapter, context or cache requires a new manifest and fresh
evaluation. Keep old evidence visible as stale. Acceptance records review of
the submitted evidence; it does not authorize deployment or certify hidden
tensor semantics. Preserve human-readable control records during the run, not
only a final explanation generated by the model.

## Pilot procedure and evidence

1. Select one task with a checkable outcome. Before running it, pin the model,
   runner, tools, task input, evaluation rule, generation settings and resource
   budget. Record license and access checks for model, data and implementation.
2. Run the full-context/prefix, text-summary and latent conditions against the
   same available information, tools and budget. Record cache conditions and
   setup separately. A missing import interface is an unsupported condition,
   not a failed quality result or an implicit fallback.
3. Save a run record for every attempt, including failures and retries. Record
   task outcome, input/output tokens where defined, total latency, transferred
   bytes, peak device memory, setup, serialization/import time, latent steps,
   retries and measured resource cost. Unavailable values remain unavailable;
   they are never entered as zero.
4. Exercise wrong hashes, wrong model/adapter revisions, stale context,
   oversized state and absent/revoked authorization. Each must reject before
   import. Record one successful Synbios evidence/review lifecycle and rejected
   stale-evidence, stale-review, revoked-grant and self-review attempts.
5. Ask an independent reviewer to inspect the pinned inputs, raw records,
   calculations, rejection evidence and artifact bindings. Reproduce the first
   task before expanding to a frozen held-out set and repeated runs.

A run record should include `experiment_revision`, `condition`, `task_revision`,
`manifest_revision`, `manifest_sha256`, `seed`, `cache_state`, `started_at`,
`outcome`, the measured metrics above, an `error` or rejection reason, and links
to the raw evidence and review. Use opaque experiment-local identifiers, never
private machine paths or credentials. This is a recording checklist, not an
implemented schema or claimed measurement.

Before expansion, set the task-specific quality margin, improvement threshold,
repetition count and comparison method. Continue only if held-out quality stays
within that margin and total cost or latency improves after all overhead.
Stop on unreproducible gains, compatibility ambiguity, protected-field loss or
material regressions. Dynamic LoRA and persistent edits stay outside this pilot.

Command compression is a separate experimental factor: compare compact JSON
with the exact reviewed ABIOS/3 implementation when available. Codec round
trips, model comprehension and state-transfer quality are different claims.
Do not infer one from another or use synthetic token totals as quality evidence.

## Review and execution readiness

The RFC can be reviewed before a runner is selected. Execution remains pending
until the runner/model/task revisions, licenses, budget, outcome metric and
thresholds are recorded. No experiment results are included in this proposal.
The study remains outside mandatory repository gates, consistent with
[the evaluation-harness decision in #7](https://github.com/Moissanite-Labs/abios/issues/7#issuecomment-5743621439).

An eventual weight-delta study must additionally bind the exact base checkpoint,
target modules, adapter rank/format, application scope, resulting artifact
identity, regression task set and verified restore-to-baseline procedure.

## Sources and attribution

This proposal develops the boundaries in [#42](https://github.com/Moissanite-Labs/abios/issues/42)
and preserves its distinction between research motivation and implementation
evidence. Its source assessment points to [LatentMAS v4](https://arxiv.org/html/2511.20639v4),
[Interlat v5](https://arxiv.org/html/2511.09149v5),
[HyperTuning](https://proceedings.mlr.press/v202/phang23a.html),
[ROME](https://rome.baulab.info/) and [MEMIT](https://memit.baulab.info/).
These are different methods with different compatibility assumptions; none is
a general interoperability contract for closed model APIs.

The Synbios boundary is grounded in its pinned
[implementation contract](https://github.com/Moissanite-Labs/synbios/blob/fe3e0d908d08cf01d01dab769014bbbf2fbba89c/docs/implementation-contract.md).
ABIOS's MIT license does not grant rights to model weights, datasets, research
implementations or sibling repository code. Check their actual terms before
copying code or running a prototype. No source code, tensor, dataset or shared
conversation transcript is incorporated here.
