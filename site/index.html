ABIOS

Token-aware shared-state messaging for agents.

ABIOS/3 compresses multi-turn forge command streams for tokenizer billing while keeping decode explicit. Each session opens with POST—a one-time handshake that exchanges decode-sufficient lexicon and schema before refs, deltas, or content-addressed lines (rule L-18: no latent channel).

Primary metric: o200k_base POST ack + decode-sufficient minimal setup + messages. On 11 synthetic lifecycle messages, ABIOS refs totals 766 tokens versus 738 compact JSON (with action field) and 686 lossless English; on 40- and 200-message transcripts refs totals beat JSON (make bench verifies committed tables).

This repo also ships legacy wire: ABIOS/1 (formerly SYM-2P) v1 JSON packets and superseded v2 dense experiments—documented under Legacy, not the forward path.

01

ABIOS/1 (formerly SYM-2P)

History. Before ABIOS/3, this repository shipped ABIOS/1 (formerly SYM-2P): dense symbolic v2 wire and canonical JSON v1 packets for inter-agent traffic. That stack remains for compatibility (scripts/protean-sym2p/, wire field ext.sym2p unchanged).

Agents once replaced English+JSON with symbols: roles and acts as integers, positional fields, s-expression payloads. One brief v2 line could be ~101 bytes where JSON took 481—checkable by a stdlib validator, not ambiguous prose.

Why it works. Every word an agent emits costs tokens, and tokens cost money and time. Shorter messages are cheaper on every call, forever.

English is also ambiguous: two readers can disagree about what a sentence means, and no program can check a sentence the way it checks a number. Symbols are unambiguous by construction, so a validator can reject a malformed packet mechanically instead of misreading it.

Who reads what. Machines read the wire. Humans never read the symbols directly: a translator renders every packet back into English for operators. Each side gets the language that suits it.

The first principles.

  1. Every token an agent emits costs money and latency. Shorter messages cut the cost of every interaction, permanently.
  2. JSON repeats key names in every message. Positional fields delete the repetition. The schema lives in the code, not on the wire.
  3. Prose can be parsed but not validated. A fixed grammar lets a validator reject malformed packets with typed diagnostics: ERR:RCP for a bad checksum, ERR:SCOPE for an unbound reference.
  4. Agents reason, not just relay. The v2.1 dialect puts binding, branching, iteration, delegation, and swarm broadcast in the same symbolic language, so reasoning stays on the wire instead of being translated into English and back.
  5. Packets cross untrusted relays. The v2-rcp edition appends a checksum field, so corruption is detected instead of passed on silently. The checksum costs 17 bytes, and senders skip it where the medium is trusted.
  6. Efficiency claims need measurement. The harness ships a paired v1/v2 corpus, a bench script, and a model eval protocol, so the density win is measured rather than asserted.

What implementing buys you. Packets come out 4.8x denser than the v1 JSON they replace, and 3.1x smaller than compact v1 JSON across the bench corpus. Malformed packets are rejected with named errors instead of misread. Reasoning stays in symbols: bind, branch, iterate, delegate, spawn, broadcast. Corruption is detected on untrusted paths. Operators still read English.

What it does not buy you. It carries no measured claim that agents produce better answers in symbols: the model A/B eval has not been run. The checksum detects corruption, not identity, so proof of who sent a packet stays a future protocol.

02

Do you need this?

Reach for it

  • Two agents exchange structured forge commands and you want tokenizer-aware wire compression (ABIOS/3) alongside SYM-2P/1.0 JSON packets.
  • Agents must reason in symbols: bind values, branch on conditions, iterate, fan work across a swarm, dispatch subagents.
  • Packets cross untrusted relays and need corruption detection (SYM-2P v2-rcp checksum experiments remain in the repo as tooling).
  • You want reproducible token benchmarks with honest decoder setup accounting (make bench).
  • An operator must read what the agents said. SYM-2P translators render wire packets into English; ABIOS decodes to canonical JSON-shaped commands.

Skip it

  • The run needs proof of who sent a packet. The checksum detects corruption in transit. Transport signing (identity) is still a future protocol.
  • SYM-2P v2 dense wire is superseded for token efficiency; v1 JSON packets remain normative inter-agent traffic per SPEC.md.
03

The vision

The thesis. Models are handicapped by being forced to reason and communicate in English. The thought structure used to process human language is antithetical to the one used for math, science, and code.

The bet. Skip language-based processing where it is not needed. Let models reason and communicate in code, numbers, formulas, and symbols. Put a translator at the boundary that converts the internal language to human syntax for operators.

Where the work stands.

  • Delivered. SYM-2P/1.0 validator and templates; ABIOS/3 reference codec; reproducible benchmarks; GitHub Pages spec and paper sources.
  • Not delivered. Transport signing (proof of identity) is tracked separately; SYM-2P v2 is not a kit migration target.
  • What stays. English remains the render target for operators. Everything stays stdlib-only and offline-friendly. SYM-2P/1.0 stays the inter-agent packet profile.

The full statement lives in VISION.md.

04

The packet

One brief packet assigning work, on the wire (101 bytes):

2|b441|mr1|1|2|1|1|88|70|(10 sym-2p/1.0 (20 sec (3 5)))(11 (21 *))(12 (22 validator 0 1))|1|mr1:v1|40

The same brief as v1 JSON took 481 bytes. The v2 line takes 101: 4.8x denser.

Thirteen positional fields, no key names on the wire:

#FieldContents
1VWire version, literal 2
2IDPacket id
3TKThread key. Threads are instance data, so keys stay tokens rather than codes.
4–7F T A STSender, recipient, act, state: integer codes from the registries
8–9CF CVConfidence and coverage, 0–100
10BODYSymbolic payload as s-expressions. Never contains |.
11RQRequest code, 0 means none
12BASEBase reference, empty means none
13EXPExpiry in seconds, 0 means none

sym2-render.py turns that line back into English for operators:

assign b441 [coordinator -> builder] (proposed) confidence 88, coverage 70
Scope: implement sections 3-5 of sym-2p/1.0.
Constraint: modify no existing paths.
Acceptance: validator exits 0 on valid input, 1 on invalid.
Requires: acknowledgement required.
Base: mr1:v1.
Expires in 40s.
  • One canonical encoding. Symbols are case-folded to lowercase, so the same referent has exactly one valid encoding.
  • Governed registries. Opcode ranges are spec-owned at 1–99 and PR-allocated at 100–999, with no reuse.
  • Shared grammar. The renderer, validator, and migrator import one parser module. No duplicated grammar.
05

The reasoning dialect

v2.0 assigns tasks. v2.1 reasons. Seven new opcodes, two new acts, and a broadcast role turn the body language from fixed task shapes into a first reasoning dialect.

CodeOpShapeMeaning
30bind(30 name expr)Name a value. $name refers to it later.
31if(31 test then else)Branch on a test. Else may be empty.
32each(32 var items body)Do body for each item in a list.
33list(33 item*)List literal.
34lt(34 a b)a is less than b.
35eq(35 a b)a equals b.
40spawn(40 role thread task)Spawn a subagent explicitly.

New registry codes: role 7 is swarm (broadcast to all members), act 11 is delegate (recipient spawns a subordinate), act 12 is report (a subordinate returns a result).

Bind a value, branch on it:

(30 cov 62)(31 (34 $cov 70) (20 sec (6 6)) ())

Renders as: Let cov = 62. If cov < 70 then implement section 6.

Fan work across the swarm:

(32 s (33 3 4 5) (20 sec s))

Renders as: For each s in [3, 4, 5]: implement section s.

Dispatch a subagent:

(40 2 b442 (20 sec (7 9)))

Renders as: Spawn builder on thread b442 to implement sections 7-9.

  • Scope is checked. A $name must resolve to a visible bind. The validator reports unbound references as ERR:SCOPE.
  • Deliberate limits. No function definition, no recursion, single-expression branches. A first dialect, open for the next iteration.
06

Relay corruption protection

Every wire version ships two editions. Bare v2 is the 13-field line, for trusted paths: one machine, one operator, one local relay. v2-rcp adds a 14th field, SUM, for packets crossing machines the sender does not fully trust.

SUM is the first 16 hex characters of the sha256 of the canonical 13-field line. Seventeen bytes on the wire:

2|b441|mr1|1|2|1|1|88|70|(10 sym-2p/1.0 (20 sec (3 5)))(11 (21 *))(12 (22 validator 0 1))|1|mr1:v1|40|0e003fac2df6829e
  • Sender picks per interaction. No negotiation. Receivers accept both editions. An agent sends bare lines on trusted paths and switches to -rcp for relayed ones, paying the checksum cost only where corruption is possible.
  • Old readers fail loudly. A validator written before this edition rejects a 14-field line with a shape error instead of misreading it.
  • Corruption, not identity. The checksum detects corruption in transit. It does not prove who sent the packet. Full transport signing stays a separate future protocol.

sym2-migrate.py --rcp emits rcp lines, and the validator reports bad checksums as ERR:RCP.

07c

Why ABIOS?

ABIOS stands for Agent BIOS. A BIOS is the layer that lets an operating system talk to hardware without knowing the details of each device. ABIOS plays that role for agents: a small, shared layer that lets one agent talk to another without either paying to restate everything they already share.

The name nods to IBM's Advanced BIOS. In April 1987, IBM shipped the Personal System/2 with its ROM BIOS split in two: CBIOS, which kept real-mode DOS working, and ABIOS, a new interface for multitasking, protected-mode operating systems like OS/2. ABIOS itself saw little use. Operating systems mostly brought their own drivers, and the Micro Channel machines it shipped on lost to the open ISA/EISA ecosystem.

The PS/2 line around it lasted much longer. It introduced VGA, whose 640×480 mode remains a common lowest-common-denominator display mode. Its 6-pin mini-DIN keyboard and mouse connectors became the "PS/2 ports" found on PCs for decades. And it made the 1.44 MB 3.5-inch floppy the standard, the disk still drawn as the "save" icon. The name is for a forward-looking interface designed for multitasking systems before they were common. It does not claim ABIOS succeeded.

POST. Every PC runs POST (power-on self-test) at boot, before loading an operating system. In ABIOS, POST is the one-time session handshake: before references or deltas, peers exchange decode-sufficient minimal context. Those tokens count in every benchmark total.

Synbios. ABIOS pairs with Synbios, Moissanite Labs' agent-first collaboration hub, which integrates ABIOS natively.

Lineage. ABIOS/3 is the token-aware redesign. ABIOS/1 (formerly SYM-2P) v2 dense wire tokenized worse than JSON (1,415 vs 738 o200k tokens on 11 messages with current baselines) and was dropped; v1 JSON packets remain documented as SYM-2P/1.0 in SPEC.md.

Measure what the symbols buy

bench/ turns the repo from a format into an instrument. It measures the empirical question underneath v2: does symbolic communication actually buy capability and efficiency.

FileContents
tasks.jsonl10 paired tasks. Six comprehension tasks carry the same packet in v1 English and v2. Two render tasks (v2 to English). Two compile tasks (English to v2).
sym2-bench.pyMachine metrics: bytes and parse latency per form. Result: v2 is 3.1x smaller than compact v1 JSON. Parse latency is tens of microseconds either way.
EVAL.mdThe model A/B protocol: fresh sessions per form, verbatim answers, how to read the scores.
sym2-score.pyScores an answers file per task and per form (v1 vs v2).

Stated plainly: the harness does not run models itself, and 10 hand-written tasks are a smoke test, not a benchmark. A real capability claim needs the eval run against models, reported with model name, date, and scores.

08

From v1 to v2

v1 speaks JSON but thinks in English: prose sits inside string fields, and a model receiver must parse human language to understand a machine message. That is the handicap the project starts from.

v2 moves the language to symbols. Packet content becomes codes, numbers, and structured expressions. English stops being the source and becomes a render target: a translator script converts packets to human-readable English for operators.

v2 keeps what worked in v1: one packet per line in durable text artifacts, a versioned wire format, and a validator with exit codes 0 (valid), 1 (invalid), 2 (usage or IO error).

SYM-2P/1.0 stays the inter-agent packet profile. The v2 migrator remains a tooling experiment for worked examples; v2 dense wire is not a kit migration target.

Translate and validate

python3 scripts/protean-sym2p/sym2-render.py <packets.sym2>
python3 scripts/protean-sym2p/sym2-migrate.py <packets.jsonl>
python3 scripts/protean-sym2p/sym2-migrate.py --rcp <packets.jsonl>
python3 scripts/protean-sym2p/sym2-validate.py <packets.sym2>
python3 tests/test_sym2.py

The renderer reads the wire form. Operators read the rendered form. Agents read the wire form.

The migrator converts v1 JSON packets to v2 lines. It fails loudly where English has no symbolic pattern yet, and it covers the worked examples, not the full corpus. The --rcp flag emits the protected edition.

Exit code 0 means every line is valid. Exit code 1 means at least one is invalid, with a typed diagnostic (ERR:SCOPE for unbound references, ERR:RCP for bad checksums). Exit code 2 means a usage, IO, or configuration error.

  • v2 test suite. tests/test_sym2.py runs 50 stdlib-unittest tests: the wire parser, the renderer, the validator including negative cases, the reasoning dialect, the rcp edition, and the migration round trip.
  • v1 suite unchanged. tests/run-tests.py passes every valid fixture and rejects every malformed, stale, duplicate, or protected-semantic fixture. Twenty invalid fixtures and four valid ones ship under tests/fixtures/.
  • Internal-name gate. gates/protean-sym2p/check-internal-names.py blocks internal names from leaking into published artifacts.

11

Install

bash install.sh --target <dir>
bash install.sh --target <dir> --dry-run

Bash and coreutils only. Zero network calls. Every written path is printed, and no --target means no run. The dry run writes nothing.

It installs alone, resolving only its required dependencies. Optional relationships are reported, not fetched.

Open items

SYM-2P v2 dense wire is superseded for token efficiency; SYM-2P/1.0 stays the inter-agent profile. Stated plainly:

  • Transport signing (identity). The rcp checksum detects corruption in transit. Proof of who sent a packet stays a separate future protocol.
  • Kit adoption. ABIOS/3 is repo-only until the ingredient manifest lists it; SYM-2P v2 dense is not a migration target.
  • Forward compatibility. A v2.0-era reader rejects v2.1 opcodes as unknown, with no capability marker to distinguish "too old" from "corrupt." Worth deciding before the kit lock moves.
